# stasis-v0.3.3-performance-rwa-v1 — preregistered Windows RWA performance protocol

Status: `v1-preregistered-no-measurements`

Pre-measurement correction (2026-09-03): the first hosted execution, GitHub run
`33842085298`, stopped during server-identity preflight and produced no RWA
timing observations. It showed that the previously hard-coded generated-build
hash was checkout-path-dependent for the causal reason documented below. This
correction preserves the frozen workload and `build:ci` command while sealing
the generated bytes at startup and postflight. The run remains disqualified and
is not a benchmark sample or rerun authority.

This protocol measures one narrow question: on the same Windows host, how long
does each runner take to execute the complete frozen eight-intent RWA
authentication workload when one external monotonic boundary includes runner
startup, all seeds, intents and behavioral oracles, and runner cleanup?

It is not a Cypress API-compatibility claim, a general React benchmark, or a
mechanism for upgrading compatibility evidence. A performance authority exists
only after both runners remain behaviorally supported at 8/8 in every retained
warm-up and timed sample.

Identity verification, candidate extraction/import, checkout inspection,
server byte/listener verification, and host inspection happen before any
performance boundary. An integration must fail closed if any frozen identity
does not match; this protocol does not time a degraded or substituted runner.
The retained hosted provenance includes provider, repository, workflow, job,
run ID/attempt, workflow-source SHA/ref, and the executing harness HEAD/tree.
The harness must have no tracked or untracked non-ignored changes. Ignored
dependency, candidate-input, and generated-artifact directories are outside the
source-identity scope and remain covered by their dedicated byte identities and
fresh-artifact gates.
Before any timing boundary, the exact installed RWA `node_modules`, Cypress
package, ts-node package, Cypress runtime trees, and `Cypress.exe` byte count
and SHA-256 must match the frozen identities. The public wrapper retains those
path-free values for exact replay.

The RWA `build:ci` command enables Istanbul instrumentation through Vite. Its
generated JavaScript embeds the absolute checkout directory; that path-derived
instrumentation changes both the JavaScript and source-map bytes, so their
hashes are intentionally not portable across otherwise identical hosted
checkouts. After all frozen source, dependency, runtime, and build-command
checks pass, the performance job therefore discovers the generated build-tree
and frontend-response identities at server startup. Every served build file
must byte-match the local generated file. The discovered path-free identities
are retained in the public artifact and must match exactly at postflight on the
same still-running server processes. Discovery happens outside all timing
boundaries and does not permit a source, dependency, command, server, or
workload substitution.

## Complete denominator

Every lane executes all eight `it(...)` cases in exact source order:

1. `auth-01-unauthenticated-redirect` — unauthenticated redirect to sign-in.
2. `auth-02-login-home-redirect` — login and home redirect.
3. `auth-03-remember-user-thirty-days` — remembered login for 30 days.
4. `auth-04-signup-login-onboard-logout` — sign-up, login, onboarding, bank
   account creation, and logout.
5. `auth-05-login-validation-errors` — login validation errors.
6. `auth-06-signup-validation-errors` — signup validation errors.
7. `auth-07-invalid-user` — invalid-user error.
8. `auth-08-invalid-password-existing-user` — invalid password for an existing
   user.

The frozen case and oracle definitions come from `src/rwa/cases.mjs`. Sixteen
Percy snapshots remain excluded visual diagnostics, not additional cases or
oracles. Missing, skipped, failed, retried, unsupported, or malformed cases
stay in the denominator and invalidate the performance authority.

## Same-host binding

Preflight returns one privacy-safe host identity with exactly these fields:

```text
platform = win32
arch = x64
runnerOs = Windows
imageOs
imageVersion
cpuModel
logicalCpuCount
identityDigest
```

`identityDigest` is SHA-256 over the canonical JSON projection of the first
seven fields in the schema's fixed order. It excludes machine name, username,
paths, IP addresses, and environment variables. Preflight must attest
`sameHostVerified: true`, and every Cypress and Stasis lane result must repeat
the same digest. Both runners receive the same server handle from the one
out-of-boundary server startup.

The server-start callback must either return one ready cleanup handle or roll
back before rejecting. The orchestrator also invokes the stop callback with a
null handle and `startupComplete: false` after a rejected acquisition so an
integration can reap any discoverable partial process state.
Startup must retain the frozen clean `data/database.json` bytes. Postflight may
retain either those same clean bytes or the one already declared newline-only
runtime state, with its exact hash; the reverse transition and every other
tracked mutation are forbidden. Both endpoints remain retained and must
independently pass the frozen checkout inspector.

## Fresh-state and runner contract

Each callback is a complete lane, not a per-case microbenchmark.

- Cypress starts a fresh Cypress/Electron engine for the lane, runs the one
  unmodified spec, retains upstream test isolation, calls the existing seed
  reset before each case, and resolves only after Cypress/Electron cleanup.
- Stasis uses one fresh v0.3.3 native process and controlled session per intent,
  calls the same seed reset before each intent, evaluates the frozen behavioral
  oracles, closes every session/runtime, and resolves only after the eighth
  cleanup.
- Both callbacks return all eight ordered case records, seed and intent counts,
  every frozen oracle ID and status, one attempt per passing case, engine-start
  count, zero retry/sleep/dropped-failure counts, the host digest, and
  `cleanupComplete: true`.
- A false or missing cleanup attestation is a malformed lane result. Collection
  stops because the next lane cannot be claimed fresh. A thrown callback is
  retained once as `runner_error` and is never retried.
- A structurally valid behavioral failure with complete cleanup is retained and
  the remaining schedule continues. Its duration is never filtered, replaced,
  or rerun.

No runner callback may perform identity/preflight work, start or stop the RWA
servers, write reports/artifacts, add sleeps or polling, or retry a failed
intent. Cypress's built-in command/assertion retry semantics remain an explicit
semantic difference; setting runner retries to zero does not remove them.

## Timing boundary

One injected monotonic nanosecond clock function is shared by every timed lane.
For each full-lane callback the orchestrator performs exactly:

```text
startNs = monotonicNow()
result = await fullLaneCallback()
endNs = monotonicNow()
durationNs = endNs - startNs
```

`endNs` must be strictly greater than `startNs`, and each later sample's start
must be greater than or equal to the preceding sample's end. The raw validator
therefore proves local duration replay and the global order from the one clock.
A throwing, non-bigint, negative, stationary, or backwards clock creates one
retained `clock_error` slot, invalidates authority, and stops collection without
retry. Partial clock boundaries are retained as canonical strings or null; no
duration is invented.

The end read occurs immediately after callback settlement and before result
validation. Therefore the boundary includes:

- Cypress/Electron startup, or all eight Stasis native process startups;
- all eight server-owned database seed resets;
- all eight frozen user intents;
- every preregistered behavioral oracle; and
- graceful/fail-stop runner cleanup through the callback's cleanup-complete
  settlement.

The boundary excludes:

- candidate, SDK, Cypress, RWA checkout, server, and host identity/preflight;
- RWA frontend/API server startup and shutdown;
- the one warm-up for each implementation;
- runner-result schema validation and authority-summary replay; and
- JSON/report/artifact serialization and I/O.

Per-test Cypress durations, per-case Stasis `wallTimeMs`, wall-clock timestamps,
and internal virtual time are not performance inputs. Only the common external
`durationNs` values are eligible for paired statistics.

## Fixed execution schedule

The servers start once after preflight. Then the orchestrator performs exactly
one untimed, retained, eight-intent warm-up for A and one for B, in that order:

```text
A = Cypress
B = Stasis v0.3.3
warm-up = A, B
```

Ten timed pairs follow, alternating order to balance first/second position:

| Pair | Order |
| ---: | :---: |
| 1 | AB |
| 2 | BA |
| 3 | AB |
| 4 | BA |
| 5 | AB |
| 6 | BA |
| 7 | AB |
| 8 | BA |
| 9 | AB |
| 10 | BA |

This yields ten timed samples per implementation and twenty retained timed lane
records. There are no discretionary extra warm-ups, samples, outlier reruns,
or early successful stopping rules.

## Authority and failure rule

The raw authority is `valid` only when all of the following are true:

- both warm-ups are structurally valid and behaviorally supported 8/8;
- all twenty timed lane records exist in the preregistered AB/BA order;
- every Cypress timed lane passes all eight frozen cases with one attempt each;
- every Stasis timed lane is behaviorally supported 8/8, with each success
  retaining `PASS_WITH_SEMANTIC_DIFFERENCE`;
- every lane uses fresh state, seeds every intent, includes every required
  engine startup, and attests cleanup before returning;
- every lane reports zero runner retries, sleeps, and dropped failures;
- all lane host digests equal the preflight host digest; and
- the external RWA server shutdown completes outside the timing windows.

One failing runner invalidates the entire authority. A paired delta, median,
ratio, confidence interval, or faster/slower claim must not be computed from or
published for an invalid authority. Raw failures and their measured durations
remain present so the failure cannot be silently dropped.

## Semantic-difference disclosure

Stasis success means behavioral support under the case-specific preregistered
differences in `rwaAuthSemanticDifferences`; it never means exact Cypress
semantics. The raw result repeats the active v0.3.3 definition catalog, each
case's exact active difference IDs, and separately labelled resolved lineage.
In particular, the comparison retains:

- deterministic `settle()` versus Cypress command/assertion retry behavior;
- value replacement versus keyboard/input sequences;
- semantic activation versus Cypress actionability and pointer synthesis;
- focus transfer versus direct blur;
- semantic DOM presence/text versus layout-backed visibility;
- excluded Percy/layout snapshots;
- disabled-attribute, exact-selector, network-audit, and GraphQL-operation-name
  observer differences;
- public current/final URL authority rather than hidden page evaluation;
- viewport branch differences where registered; and
- one Cypress browser/spec lane versus eight fresh Stasis native processes.

The historical `persistent-cookie-profile-gap` remains visible only as frozen
port lineage. It is explicitly recorded as
`positively-supported-in-v0.3.3` under `controlled-web-session-v2`, removed from
the active v0.3.3 semantic-difference IDs, and must not be reported as a current
unsupported boundary.

Consequently, any valid timing summary is scoped only to these two frozen ways
of producing the eight registered RWA outcomes on the recorded host. It cannot
be generalized to Cypress feature compatibility, arbitrary web applications,
or exact browser-semantic equivalence.

## Raw-data contract

`stasis-v0.3.3-performance-rwa-raw-v1` retains:

- the protocol, track, frozen source, host, complete plan, and semantic catalog;
- both untimed warm-up result envelopes without timing fields;
- every attempted timed slot with pair/order/position, runner, canonical decimal
  `startNs`, `endNs`, `durationNs`, result or projected error, and status; a
  `clock_error` uses an explicitly nullable partial timing instead of a duration;
- server lifecycle attestations showing startup/shutdown were outside timing;
  and
- a replayable authority status, fixed planned/completed counts, per-runner 8/8
  counts, retained-failure count, and deterministic reason codes.

The validator rejects unknown/missing keys, host digest drift, changed source or
semantic disclosure, schedule drift, zero/backwards/globally reordered or
otherwise nonreplayable timing,
case/order/oracle drift, erased Stasis semantic differences, false cleanup,
nonzero retry/sleep/drop counts, and an authority summary that does not replay
from the raw records. Projected failures use closed name/code vocabularies and
never retain arbitrary callback messages.

No measurement produced before this file and its implementation are committed
under the preregistered protocol is authoritative evidence for this protocol.
